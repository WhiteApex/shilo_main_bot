# Telegram бот для онлайн-мероприятий

Лёгкий и дружелюбный Telegram-бот на **aiogram 3**, который помогает рассказывать об онлайн-мероприятиях, собирать заявки и управлять контентом без программиста.

## Возможности
- Приветственная витрина с афишей, описанием и быстрыми кнопками «Мероприятия», «О нас», «Написать нам».
- Каталог активных событий из SQLite с карточками, записью по форме (ФИО, телефон, email) и автоматической отметкой «Вы записаны ✅».
- Напоминания за 3 дня, за 1 день и в день события (09:00) по расписанию APScheduler в часовом поясе Asia/Yekaterinburg.
- После окончания события карточка может быть переведена в режим «Событие прошло» с отчётным media file_id.
- Админ-панель по команде `/admin` с проверкой по списку ID:
  - Добавление, редактирование, удаление событий и предпросмотр карточки до публикации.
  - Обновление стартового экрана и блока «О нас» без кода.
  - Автоматические бэкапы SQLite после правок и по расписанию, логирование действий, отправка уведомлений в админ-чат.
  - Просмотр базовой статистики (старты, клики, записи, доставки) и ежедневный экспорт CSV.
- Хранение UTM-меток из `start_payload`, аналитика в таблице `metrics`.
- Seed-скрипт и пример JSON-контента для быстрого запуска демо.

## Стек
- Python 3.12
- aiogram 3
- SQLAlchemy 2 + SQLite (готово к замене на PostgreSQL через переменную `DATABASE_URL`)
- APScheduler 3
- Docker (multi-stage), docker-compose, Makefile

## Быстрый старт
```bash
cp .env.example .env
# заполните переменные TELEGRAM_TOKEN, ADMIN_IDS, SUPER_ADMIN_ID и т.д.

poetry install
poetry run alembic upgrade head
poetry run python seed.py
poetry run python -m app.main
```

### Через Docker
```bash
docker-compose up --build
```

Контейнеры:
- `bot` — приложение на aiogram
- `scheduler` (встроен в бот) — фоновые задачи (напоминания, экспорт, бэкапы)

## Структура проекта
```
app/
  config.py         # настройки и переменные окружения
  main.py           # точка входа бота
  handlers/         # обработчики start, events, admin
  keyboards/        # inline-клавиатуры
  services/         # доменная логика (события, напоминания, бэкапы, экспорт)
  db/               # модели, сессии, репозитории
  metrics/          # учёт действий пользователей
  utils/            # хелперы (логирование, время, utm)
alembic/            # миграции БД
backups/            # сюда складываются резервные копии
json_examples/      # примеры JSON-контента
 docs/db.mmd        # Mermaid-схема базы данных
seed.py             # скрипт для наполнения демо-данными
```

## Переменные окружения
| Переменная | Описание |
|------------|----------|
| `TELEGRAM_TOKEN` | Токен Telegram-бота |
| `ADMIN_IDS` | Список ID администраторов через запятую |
| `SUPER_ADMIN_ID` | Главный админ, получает бэкапы и экспорт |
| `DATABASE_URL` | Строка подключения SQLAlchemy (по умолчанию SQLite) |
| `MANAGER_USERNAME` | Username менеджера для кнопки «Написать нам» |
| `BACKUP_EMAIL` | Почта для внешних бэкапов (заглушка) |
| `SENTRY_DSN` | DSN для Sentry (заглушка) |
| `ADMIN_LOG_CHAT_ID` | ID чата для логов и алертов |
| `TIMEZONE` | Часовой пояс (по умолчанию Asia/Yekaterinburg) |

## Команды Makefile
- `make format` — запуск ruff (форматирование + lint)
- `make bot` — локальный запуск бота через poetry
- `make seed` — прогнать сиды
- `make migrate` — применить миграции

## Аналитика
Метрики пишутся в таблицу `metrics` с типами: `start`, `click`, `subscription`, `delivery`, `read` (зарезервировано). Экспорт CSV и ежедневные уведомления позволяют отслеживать динамику без входа в БД.

## Бэкапы
- Автоматический бэкап SQLite после любого изменения через админ-панель.
- Еженедельный бэкап по расписанию (понедельник 08:00, часовой пояс проекта).
- Бэкапы отправляются главному администратору личным сообщением и сохраняются в каталоге `backups/`.

## Дополнительно
- В `data/content.json` хранятся тексты стартового экрана и блока «О нас» (заглушки).
- Напоминания отправляются трижды перед событием. При необходимости можно поменять расписание в `app/utils/time.py`.
- Миграции Alembic содержат полную схему таблиц.
- Mermaid-схема в `docs/db.mmd` помогает быстро понять структуру БД.
